# 流畅度与动画过渡验证

2026-10-06（Asia/Shanghai），基于当前 0.6.0 工作区实施。保留原有布局、正文采集时机、发送事务、草稿与用户附件保护。

## 界面与实现

- 共享 `src/motion.js` 管理进入 180ms、退出 120ms、列表换位 150ms 的动画。按钮反馈为 120ms；弹层位移 4px，内容切换只淡入，不动画长正文或弹窗高度。
- 浮层、原生设置／授权／诊断／备份弹窗、引用标签与状态提示使用统一动画。关闭期间立即 inert；重开取消旧退出完成回调。外部点击保留新焦点，Esc／关闭按钮恢复原入口焦点。网站发送按钮点选时立即退出设置弹窗，权限申请与发送不等待动画。
- 跟随系统减少动态效果，并在偏好切换时终止正在进行的动画。原生模态焦点和配置操作期间的 Esc 拒绝规则继续生效；销毁会清理动画、帧任务与观察器。
- 标签使用完整来源和预设输入的差量比较，跳过未变状态的正文展开与 DOM 写入。预设勾选、提示文本与弹层坐标仅在变化时写入；排序成功保留列表节点、滚动位置及焦点。
- 控件观察仍检查原站控件、来源祖先、显式选择器和连接提示；纯流式文本更新不触发重新挂载。保留每秒兜底检查与发送前完整校验。
- 拖动排序在同一帧中处理指针和边缘滚动，使用不含动画变换的布局坐标判断位置。只在顺序或插入标记变化时修改 DOM，松手先处理最终指针位置再保存一次。大量预设锁定／解锁控件时不对全部按钮做透明度动画。

## 可重复测量

新增浏览器组 `motion`，纳入 `npm run test:browser`。单独运行：

```sh
npm run build
node scripts/test-browser.mjs motion
```

该组使用真实 Chromium、当前源码的临时测量构建和本地模拟后台响应，并验证当前 `dist` 的侧栏弹窗。测量钩子不会写入生产构建。它不读取真实账号或接入用户现有浏览器配置。

基线在改动增强层前，通过相同脚本的 `--baseline` 记录；优化后使用同样的约 70,000 字正文、36 次输入、60 帧回复文本更新、弹层滚动，以及 100 条自建预设排序。计数边界如下：

| 场景／指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 普通输入：长正文模板展开 | 37 | 0 |
| 普通输入：增强层 Shadow DOM 变更记录 | 112 | 0 |
| 普通输入：文档 `querySelectorAll` 调用 | 360 | 约 80 |
| 纯流式文本：文档 `querySelectorAll` 调用 | 210 | 0 |
| 闲置同步：模板展开／Shadow DOM 变更 | 1／4 | 0／0 |
| 预设排序：Shadow DOM 变更记录 | 3891 | 1040 |
| 弹层内部滚动：定位计算 | 0 | 0 |

Shadow DOM 变更计数包含排序过程中必要的控件锁定、解锁与插入标记。`querySelectorAll` 是测量代理捕获的文档调用，不等于所有选择器或布局读操作。每秒兜底检查可能跨入某次场景，调用数存在小幅浮动。

Chrome DevTools 性能轨迹保存在 `tmp/browser/motion-baseline-trace.json` 与 `motion-optimized-trace.json`，原始计数在对应 `*-results.json`。轨迹覆盖整个测量序列，包含排序动画；输入脚本的等待时间、机器负载和动画帧均会影响总耗时。这些结果证明重复工作减少，不用于宣称真实网站帧率或输入延迟提高了某个固定百分比。

最终轨迹中 `Layout` 事件由 165 次降至 109 次（累计 35.1ms → 31.4ms）；`UpdateLayoutTree` 由 142 次变为 159 次（9.8ms → 14.5ms）。新增动画仍有样式更新开销，未宣称所有指标都降低。
