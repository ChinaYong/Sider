# 灵活侧栏关联模型与原生能力验证

本阶段实现纯关联模型、跨页预设契约和可重复的原生能力探针。生产后台尚未安装新模型，设置页也尚未开放四种模式。正式集成须通过同一原站实例维持及切换能力门槛。

聊天会话由 AI 网站管理。扩展只记录标签页与存活侧栏页面的关联、切页时是否维持该页面、显示状态及当前引用来源。代码中的 `sessions` / `sessionId` 表示侧栏实例记录，不是 AI 网站的聊天会话；原站在同一页面内新建或切换聊天，不会因此新建扩展侧栏实例。草稿、附件和生成状态通过保留原页面自然维持，不由关联模型复制或恢复。

## 规则与状态

`src/side-panel-model.js` 不依赖 Chrome API。`createPanelModel()` 默认采用 `independent`；`reducePanelModel(state, event)` 返回独立的 `{ state, effects }`，不修改传入状态。`createPanelModelController({ perform, onChange })` 按窗口串行执行承载操作，新事件即时更新意图版本。

| 模式值 | 目标页没有打开的关联时 | 固定控制 |
| --- | --- | --- |
| `shared` | 承接本窗口最近实际使用的打开实例 | 不提供 |
| `independent` | 切页保持关闭，主动打开才创建独立实例 | 不提供 |
| `same-site` | 承接完整域名相同的最近打开实例，无候选则保持关闭 | 不提供 |
| `manual` | 承接本窗口固定对象，无固定对象则保持关闭 | 提供 |

四种模式都先保留目标页已打开的关联。自动承接不会合并已有实例。设置变化只改变后续规则。不同窗口独立；同站使用 `URL.hostname`，忽略协议、端口、路径，区分子域名；URL 未暴露时不猜测域名。

“最近使用”仅在主动打开或切页操作被承载层确认后更新，导航、后台同步、存活核对和可见性事件都不更新它。A、B 因历史设置各有实例时，从 B 切到未关联的 C，`shared` 选择 B。

| 状态 | 用途 |
| --- | --- |
| `sessions[id]` | 稳定侧栏实例 ID、窗口、承载实例身份 `carrierId`、打开状态及最近使用顺序 |
| `tabs[tabId]` | 当前 URL、域名、来源版本、单一侧栏实例关联 |
| `windows[windowId]` | 活动标签页、固定对象、已确认显示对象、来源、未完成意图、错误 |
| `window.source` | 当前来源身份、正文版本、关联事件版本 `epoch` 及是否可读取 |
| `window.pending` | 当前请求及 `{ windowId, revision, requestId }` 令牌；不等于已完成关联 |

固定以当前存活实例为对象，每个窗口最多一个。B 有自己的侧栏时，固定 A 不会覆盖 B；新 C 仍承接 A。在 B 取消固定，承载层须确认同一实例留给 B 后，才能解除其他成员并取消固定。固定对象的替换保留此前成员；离开手动模式清除固定标记，保留所有已打开关联。

关闭共用实例会清除该实例的所有成员和固定标记。切页隐藏保留实例和关联。最后一个成员标签页关闭后，模型结束实例并请求清理承载对象。移动窗口只有在独享实例提供同一承载身份的存活证据时才保留关联；其余情况解除该页关联并记录 `WINDOW_TRANSFER_UNVERIFIED`，不承接目标窗口其他实例。

## 事件和承载契约

| 事件 | 处理 |
| --- | --- |
| `TAB_ACTIVATED` / `OPEN_REQUESTED` | 观察当前标签页，递增窗口版本，禁用旧来源，再解析原关联或候选 |
| `MODE_CHANGED` | 更新全局策略，使未完成请求过期；保留所有已完成关联 |
| `TAB_NAVIGATED` | 保留侧栏实例关联，递增来源版本并更新域名，活动页的旧准备操作失效 |
| `PIN_CHANGED` | 仅手动模式和活动页存活实例有效；取消固定需要承载确认 |
| `CLOSE_REQUESTED` | 请求关闭活动页所属的整个实例；失败时保留关联 |
| `CARRIER_VISIBILITY` | 只更新显示与可用来源，不能创建关联或当作关闭 |
| `CARRIER_CLOSED` | 根据窗口和精确承载身份结束整个实例 |
| `TAB_REMOVED` / `WINDOW_REMOVED` | 清理成员与孤立实例 |
| `TAB_MOVED` | 明确处理窗口归属；需要同一实例存活证据才能转移 |
| `CARRIERS_RECONCILED` | 将模型记录与实际存活的窗口、侧栏实例和承载身份核对 |
| `EFFECT_COMPLETED` | 只有当前令牌可完成意图；过期响应不会提交旧来源 |

`TAB_ACTIVATED`、`OPEN_REQUESTED`、`TAB_NAVIGATED` 接受 `{ tab: { id, windowId, url, title, status, readable } }`。未知 URL 传空或不传，不用旧 URL 代替。`readable: false` 和 `status: 'loading'` 会使引用不可用。

承载接口 `perform(effect)` 返回 `{ ok, carrierId?, error?, code?, carriers? }`，其中：

- `create`：实际创建侧栏页面成功后返回新的页面实例身份。侧栏记录 ID 由模型生成，不创建 AI 网站聊天。
- `show`：显示指定存活实例，返回它的原身份。复制页面或加载相同 URL 后返回新身份，会触发 `INSTANCE_REPLACED`，不能提交共用关联。
- `unpin`：完成成员解除与归属转移，返回原实例身份；失败保留所有成员及固定对象。
- `hide` / `close`：确认暂时隐藏或整个实例关闭。承载层负责提供已完成操作的证据。
- `dispose`：只清理已退役或本次过期创建的孤立承载对象，不能清理正在使用的共享候选。
- `inspect`：核对实际存活对象，返回 `{ ok: true, carriers: [{ sessionId, carrierId, windowId }] }`。

同窗口操作串行，不同窗口可并行。新的意图在旧操作进行中就递增版本。过期创建只清理自己的新实例；过期显示、关闭或解绑结果请求核对实际承载状态，不能把旧结果提交到新标签页。清理或核对失败写入窗口错误。

`restorePanelModel(saved, liveCarriers)` 不读取浏览器存储。它需要明确的存活清单；只有窗口、侧栏记录、承载实例身份全部相同才保留关联，清除保存的显示状态、来源和未完成请求。存储恢复不证明原站页面存活，也不证明浏览器重启后草稿可恢复。

原生事件整合前须核对 `onOpened` / `onClosed` 的窗口、路径和可选标签页，以及内部操作的预期事件。无法区分“切页隐藏”和“用户关闭”的事件，不能直接转为 `CARRIER_CLOSED`。

## 跨网页预设契约

`src/side-panel-snapshot-contract.js` 定义后续增强层整合所需的身份规则；目前未接入生产输入框。

- `presetSourceKey(templateId, source)` 用预设 ID、来源标签页和完整 URL 区分重复追加。相同来源的正文版本更新仍属于同一追加位置；不同来源互不替换。
- `createPresetSnapshotIdentity(...)` 为每份材料提供独立快照 ID，并用该 ID 作为附件所有权身份。保留预设 ID、来源名称和 URL。
- `currentSourcePresetIds(...)` 只用当前来源的快照抑制当前来源的勾选展开，A 的正文快照不能跳过 B 的正文。
- `captureSourceToken` / `isSourceTokenCurrent` 同时核对侧栏实例、标签页、URL、来源版本和窗口关联版本。A→B→A 即使回到相同 URL，也不能复用最早 A 的未完成准备。

契约测试同时使用现有 `TemplateDraft` 验证不同快照 ID 可以保留 A/B 两块材料，并且编辑 A 不会损坏 B 的可重试记录。正式集成仍需将增强层中的预览、删除、附件恢复和去重从单一预设 ID 切换到快照身份，不能仅接入生成键的工具函数。

成功发送只清理当前来源临时勾选和当前草稿记录。已追加快照不自动刷新；其他来源的临时勾选保留。切页、导航、丢失授权或来源加载中使未完成准备失效；已完成材料保留。生产存储、配置导入版本和现有预设格式在本阶段不迁移。

## 冲突测试与执行

```sh
node --test tests/side-panel-model.test.js tests/side-panel-snapshot-contract.test.js
npm test
npm run build
npm run test:panel-capabilities
```

原生探针使用单独的最小测试扩展和本地 HTTP AI 页面，不替换生产后台。fixture 的 `tabs` 权限仅用于观测测试标签页，不进入生产清单。仍可设置 `SIDER_CHROMIUM`；浏览器配置、测试扩展、报告和截图保存在忽略的 `tmp/browser/`。

`node scripts/test-browser.mjs side-panel-capabilities` 也可以单独运行本组。默认命令成功表示探针正确完成并记录证据，**不等于原生承载门槛通过**。要求门槛必须通过时使用：

```sh
npm run test:panel-capabilities -- --require-gate
```

报告 `tmp/browser/side-panel-capabilities-result.json` 提供 `capabilities`、原生事件、实际 SIDE_PANEL 上下文身份、iframe 身份、加载次数、草稿、FileList、文件内容与页面状态。记录分别为“通过”“不支持”“尚未验证”，`gatePassed` 必须在所有项通过时才为真。

模型测试覆盖四种模式、全部 16 种模式转换、原关联优先、最近使用候选、完整域名、固定替换和取消、整组关闭、导航、窗口隔离与移动、过期响应、实际存活核对、每窗口串行执行，并运行 400 步混合事件序列检查不变量。

## 2026-10-09 原生能力结果

隔离 Chromium 148.0.7778.96 的本地 fixture 验证结果。下表“不支持”仅表示探针实际采用的原生 API 操作路径无法满足要求，不代表所有实现方式均不可行，也与 AI 网站聊天会话的管理无关：

| 能力 | 结果 | 证据 |
| --- | --- | --- |
| 同一窗口实例跨 A/B 连续使用 | 通过 | 原生页面与 iframe 身份不变；草稿、文件输入、UTF-8 内容、展开状态和模拟生成状态保留，加载计数不变 |
| 共用实例与已有独立实例并存 | 通过 | 两个实际存活实例身份及各自未发送材料均保留 |
| 已有独立实例转为共用 | 不支持 | 即使设置完全相同的 URL，仍创建另一窗口实例，草稿不随之移动 |
| 取消固定，原实例归当前页独享 | 不支持 | 同一 URL 的标签页实例仍是新页面，不能搬移窗口实例 |
| 同站跨域隐藏后自动恢复 | 不支持 | 禁用目标页没有隐藏窗口实例；主动关闭并等待 6.5 秒后，仅切页重新打开被用户手势限制拒绝 |
| 浏览器原生关闭按钮的整组识别 | 尚未验证 | 只验证了窗口 API 关闭事件及独立实例保留，没有点击浏览器工具栏的原生关闭按钮 |

扩展页面消息的 `MessageSender` 在本次 Chromium 中没有 `documentId`。fixture 将每个新页面的随机实例标记与尚未登记的实际 `SIDE_PANEL` 上下文对应，并再次用存活上下文核对保留结果；不会将历史遥测当作存活证据。

所测原生操作路径尚未通过完整能力门槛；跨标签页维持同一共用页面已经通过。需要继续验证原生关联与显示策略或其他承载方案，才能确定完整规则的实现方式，不能据此认定完整功能无法实现。正式四模式 UI、生产桥接重绑、跨页追加和真实 AI 网站测试均须等待可行承载方式。不能用重开对话、复制草稿或同步多个副本替代同一实例维持。
